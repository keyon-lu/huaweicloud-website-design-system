# 执行与覆盖边界

2026-10-19最新用户裁定：已调试并验证的产品页/开发者组件样式固定复用，不根据新Pixso稿重做；新稿补缺失组件/变体。优先完成基础样式、2026图标与插画验证。先读[已验证样式保护](approved-presentation-policy.md)及[基础视觉规则](visual-foundations-2026.md)。

本包类型为子规范扩展，覆盖层级为L2：在PortalUI3.0.17基础资料和用户已确认的官网裁定之上提供公开网站原型及本地检索工作流。这里的L0/L1/L2是设计规范覆盖层级，不是操作系统、账号、工具或网络权限。包本身不授予发布、购买、账号操作或外部数据访问权限。

## 来源与冲突

明确的新用户裁定按其组件、场景和日期生效；其次是当前组件/场景契约，最后是带版本的原始资料或官网样本。候选布局只能作为候选实现，不升级为华为官方规则。原始PortalUI数值与后续裁定相异时，保留原始来源，执行[当前规范](current-standards.md)记录的范围，不全量替换上游基础样式。无法判断同层来源冲突时保留当前已确认实现，列出冲突并请求裁定，不以出现次数决定。

## 工作流选择

四条工作流均为本包核心分支；均产生UI，视觉、状态、适配和无障碍规则不可因内部路由而整体不适用。其资料可能介绍AI产品，但代码没有推理、生成、推荐或流式AI运行界面；本地检索是确定性关键词检索。以后增加AI运行能力必须重判AI维度。

|任务触发|优先工作流|拒绝的候选及原因|回退|
|---|---|---|---|
|要求搜索结果、查询接口或可运行的内容检索|local-search-validation|website-composed不能提供检索API；页头查标题也不等于该业务|没有线上接口时只生成本地工程；保留业务接入缺口|
|云服务产品介绍、优势/案例/FAQ等产品楼层|website-product-floor|不以出现“AI”“资源”自动转开发者或组合页|内容不齐时省略可选楼层，必需数据缺失停止生成|
|当前已校准的开发者官网首页|developer-portal|任意开发工具产品页不因“开发者”一词使用固定首页内容|非该首页结构时改用产品/组合能力并列出未建模组件|
|解决方案、活动介绍、资源入口或文章详情展示|website-composed|介绍活动不等于报名后端；展示资源不等于检索服务|只复用已建模区块；新结构保留缺口，不借其它产品事实填充|

组合内容中出现“搜索”一词但未要求检索交互时仍按展示意图处理；同一任务同时需要内容页和检索时分别输出，不把两者混为一个离线page_type。业务目标不足以区分时先读取已有需求/资料；仍有歧义只澄清目标行为。

## 限制与恢复

Pixso转换、已登录控制台、CMS管理、生产支付/报名、全站爬取、线上部署与认证均未启用。命中这些能力时停止该分支，说明当前可复用的展示/本地能力；恢复须补相应结构/接口/权限/验收证据并重新定义工作流。禁止将缺失核心入口、来源、公共脚本或完整性失败仅标为“限制场景”后继续声称该核心链路可用。

必读资源由根入口、子工作流、page-resource-manifest及local-search契约指定；源码分发资源由runtime-manifest校验。verify-contract-docs检查维护文档链接，verify-standalone-package检查原型运行文件和路由，verify-search-template检查检索模板。所有检查都有范围，原始参考资料的可选链接不自动成为必读依赖。必读文件缺失、完整性不符时保留原产物并停止受影响工作流；其它已验证工作流可继续，交付必须说明影响范围。可选字体等资源缺失按相应契约使用明确回退。

版本变更保留历史验收文件与哈希。补充文档不自动改变页面验收范围；修改公共接口、状态或布局时重新检查依赖它的核心分支。正式静态内容评审与工程、视觉、业务验收分别记录，任何一项通过不自动升级其它项。
