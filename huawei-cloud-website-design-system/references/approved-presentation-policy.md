# 已验证样式优先与新增组件规则

2026-10-19用户裁定：此前调试并验证的产品页、开发者页组件继续严格使用已验证样式，不再根据新设计稿重做。该裁定优先于本包中历史“来源优先”描述。

1. 先匹配已验证组件。导航/页尾、产品Hero、折叠图文、方案/案例/资源/FAQ、开发者Banner/实践卡/Skills/开放能力等，复用现有组件及其适配、尺寸、颜色、图标和交互。内容可换，不以Pixso新稿替换其皮肤；不是只保留旧页面HTML而把生成组件换成新皮肤。
2. 新稿用于尚未覆盖的楼层和明确新增变体。新组件独立命名、独立样式作用域、独立资产，不修改已验证组件或其消费Token；不得将新原型计入用户历史认可。
3. 没有对应组件时，先查[2026基础规则](visual-foundations-2026.md)，确定字体层级、颜色角色、间距、圆角、图标类别、插画构图及响应式。采用最接近的已验证基础结构，说明新增部分；不得把候选组合标成既有官方组件。
4. 基础规则遇到已验证组件的明确值时保留已验证组件；只在新区域应用。设计稿中的蓝色架构图标不触发按钮禁蓝；图标尺寸72/28不能混用，插画安全距离不替代页面边距。
5. `verify-approved-presentation.mjs`保护已有运行组件的结构、CSS与所消费Token，防止后续转换悄悄改样。它是2026-10-19实现锚点检查，不补造旧页面逐视口验收。历史产物认可仍以acceptance-ledger记载的版本和范围为准。新增源稿原型不纳入这次冻结。

只有用户明确要求修改某个既有组件时才更新该组件基准及回归证据。不能为了通过检查自动刷新保护哈希。

2026-10-25本次验收修复中的`PortalSolutionCards`焦点缺陷单独记录在[逻辑修复](protected-behavior-repairs.json)：仅允许已复现问题对应的`update`辅助函数改变；原批准基准不更新，返回JSX、其它逻辑、CSS及消费Token仍逐项保护，且不得新增人工批准。验证器会拒绝修复范围外的结构／样式或逻辑变化，即使更改修复记录的当前哈希也不能绕过AST约束。这不是依据新Pixso稿重做既有皮肤。

生成前运行`node scripts/resolve-approved-component.mjs --list`或按用途查询，例如`product.folded-advantages`会选择既有`PortalFoldedMedia`及`folded-media`，不因为新稿提供相似优势组件就改选新皮肤。完整映射见[已验证组件选型](approved-component-selection.json)。新结构不在表内时继续补规范，不自动套通用卡片。
# 2026-10-25 长连续文本的容纳修复

新增 `src/styles/content-resilience.css` 仅允许 `.hc-page{overflow-wrap:anywhere}`。这是长 URL/不可断行文字撑宽页面的容纳修复，不是视觉重设计：原批准的四份 CSS、尺寸、间距、颜色和组件 JSX 保持原值；已有显式省略、预格式命令与局部横滚行为仍由组件自身规则决定。保护检查对新增文件限定精确选择器和唯一声明，不能借此追加样式。正常样本与长内容分别复验，不新增用户视觉批准。
