# 全量183条来源的转化范围

2026-10-17用户明确要求183条来源模式全部转化，不限于当前11类生成楼层。[逐条台账](pattern-conversion-ledger.json)按来源文件、节点和规则指纹保留全部记录。183是当前总范围，已部分采用的learning-links也在其中，不是另加183种互不重复楼层。

转化产物按真实用途分为floor、page、foundation或variant。楼层/页面需要公开接口、生成入口和样本；基础规范需要实际Token或适配规则及其消费入口；变体需要可选配置与单独验证。相同名称不自动合并。实际共享实现时记录canonicalPatternId和逐来源比较依据，仍逐条保留覆盖和验证，不用通用cards冒充所有结构。

每条依次核对结构与适配说明、变体状态、对应实现、公开生成入口、实际交互、响应式与长文案、来源视觉和无障碍。纯展示/基础规则的交互检查应明确为何不适用以及如何验证对应消费者，不删除检查字段以凑完成数。暗色、多语言继续遵循用户已暂缓的范围，原始来源记录仍保留。

执行时先读取该节点的设计说明、样式、素材、状态和各断点；命名索引不是完整契约。优先完成已建模的流程/场景图文，再覆盖Banner、导航、图文/卡片、筛选与内容列表、套餐/表格、表单、活动与完整页面；处理顺序不意味着后面的记录可排除。复用基础组件时核对对应版本、来源和可支持状态，缺项补实现，不静默降级。

规范冲突集中登记来源、节点、场景、候选值和受影响分支，按用户要求最后集中确认；明确部分继续构建。未裁定分支保持pending，不冒充已发布。已确认的按钮颜色、浅绿色标签、按组件保留行高、学习楼层忽略五组及最新全局栅格继续有效。

运行`node scripts/verify-pattern-conversions.mjs --report`查看逐来源进度。正式发布还必须通过`verify-expanded-release.mjs`，其中强制核对台账与目录完整一致、实际执行入口及证据和当前源码快照。源码、样式或规则变化导致证据失效时重新验证，不仅替换旧哈希。

[逐来源执行队列](pattern-execution-queue.json)提供183条记录的候选产物类型及结构/适配/交互原始节点引用。所有候选仍需核对原稿，不以批量分类代替逐条实现。已接通的文档图片和页面切换作为variant独立追踪，不按楼层数量累计。

用户最新优先级：先补可组合页面的楼层，按图文、卡片、Banner、筛选、套餐等逐来源接规范、配置、路由和示例；基础组件只在楼层依赖所需时补，不再将全部基础家族先行作为楼层转化前置。180+为待处理来源范围，含页面和变体；不缩减用户要求，也不以基础组件数量替代楼层完成量。
